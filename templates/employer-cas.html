API Documentation

Verify up to 100 certificate hashes per request. All endpoints return JSON.

1. Batch verify certificates
POST /api/cas/verify-batch Header: X-CAS-Key: cas_<your_api_key> Content-Type: application/json { "certificate_hashes": [ "3b8dddf71c2a37b6", "eeb2390f55e93db0" ] }

Response (200 OK):

{ "status": "success", "total": 2, "valid": 1, "invalid": 1, "results": [ { "hash": "3b8dddf71c2a37b6", "valid": true, "certificate_id": "RDC-XXXXXXXXXXXX", "candidate_name": "Jane Doe", "role": "Data Analyst", "industry": "HealthTech", "level": "mid", "readiness_score": 78, "verdict": "above_benchmark", "issued_at": "2026-10-15T10:30:00" }, { "hash": "eeb2390f55e93db0", "valid": false, "reason": "not_found" } ] }
2. Where do certificate hashes come from?

Every Charvak readiness certificate (issued at /readiness-check) includes a verify URL. The hash is the last segment of that URL:

# Example certificate https://www.charvakit.com/readiness/RDC-abc123def456 # Its verify URL contains the hash https://www.charvakit.com/api/readiness/verify/3b8dddf71c2a37b6 └─ this is the certificate_hash
3. Rate limits
  • Batch endpoint: 60/min per IP, 100 hashes per request
  • Monthly quota: depends on tier (500 / 5,000 / 50,000 / unlimited)
  • Quota exceeded: HTTP 400 with reason: "quota_exceeded"
